# قیمت‌نگار 1.3.5

قیمت‌نگار یک وب‌اپ/PWA فارسی، **Local-first** و آفلاین برای ثبت قیمت خریدهای واقعی، مقایسه روند کالاها و ساخت شاخص شخصی تغییر قیمت است. داده‌های عملیاتی در IndexedDB همان پروفایل مرورگر ذخیره می‌شوند؛ استفاده روزمره به حساب کاربری، API یا بک‌اند نیاز ندارد.

## امکانات اصلی

- ثبت، ویرایش، آرشیو و حذف کالا با دسته‌بندی، واحد مقایسه، برند/مدل و یادداشت
- ثبت و ویرایش خرید با تاریخ شمسی، فروشگاه، مقدار، قیمت قبل از تخفیف، تخفیف، مبلغ مؤثر و یادداشت
- جلوگیری از تاریخ آینده، مقدار/قیمت نامعتبر و تخفیف مساوی یا بیشتر از مبلغ قبل از تخفیف
- قفل شدن «واحد مقایسه» کالا بعد از اولین خرید تا تاریخچه قیمت به‌اشتباه با واحد دیگری مخلوط نشود
- قفل شدن واحد پول بعد از اولین خرید؛ Merge پشتیبان با واحد پول ناسازگار نیز متوقف می‌شود
- جلوگیری از ساخت کالای تکراری بر اساس نام + برند/مدل + واحد مقایسه
- مدیریت فروشگاه‌ها و ادغام نام‌های همسان پس از نرمال‌سازی فارسی/عربی
- جست‌وجوی فارسی روی نام، برند، دسته، واحد و یادداشت؛ مقاوم در برابر اختلاف `ی/ي`، `ک/ك`، اعراب، نیم‌فاصله و رقم فارسی/عربی/لاتین
- داشبورد هزینه ماه جاری، ۳۰ روز اخیر، کالاهای فعال و شاخص سبد قیمت
- تاریخچه هر کالا، کمینه/بیشینه/میانگین، درصد تغییر و معیار نوسان
- تحلیل دسته‌بندی‌ها، سهم هزینه، نوسان کالاها و مقایسه فروشگاه‌ها
- بازه‌های سریع ۳۰ روز، ۹۰ روز و یک سال، به‌علاوه بازه سفارشی با Date Picker شمسی
- Empty state و راهنمای شروع برای دیتابیس خالی یا داده ناکافی
- حالت روشن/تیره/سیستم و نمایش اختیاری اعداد فشرده
- یادآور پشتیبان کامل پس از رشد داده یا قدیمی‌شدن آخرین Backup
- رابط RTL واکنش‌گرا با Vazirmatn؛ فونت از dependency پروژه وارد build می‌شود و CDN خارجی لازم نیست

## UX واکنش‌گرا

سه الگوی ناوبری با مرز مشخص وجود دارد و هیچ‌وقت دو الگوی اصلی هم‌زمان نمایش داده نمی‌شوند:

- بزرگ‌تر از `900px`: Sidebar ثابت
- `621–900px`: Hamburger + Drawer
- `<=620px`: فقط Bottom Navigation

در موبایل Hamburger/Drawer کاملاً مخفی است. صفحه کالاها نیز Search را در یک ردیف کامل نگه می‌دارد؛ Category و Sort زیر آن قرار می‌گیرند و در عرض‌های خیلی کم تک‌ستونه می‌شوند. در جزئیات کالا دکمه بازگشت به فهرست و CTA زمینه‌ای «ثبت خرید» وجود دارد.

## منطق شاخص سبد قیمت

برای هر کالا در هر ماه، **میانه قیمت مؤثر** ثبت‌های آن ماه گرفته می‌شود. وقتی همان کالا دوباره قیمت‌گذاری شود، قیمت ماه جدید با آخرین قیمت قابل‌مقایسه قبلی همان کالا مقایسه می‌شود؛ لازم نیست دو ثبت در ماه‌های تقویمی متوالی باشند.

نسبت تغییر کالاهای قابل‌مقایسه با **میانگین هندسی و وزن‌دهی خودکار** ترکیب و روی شاخص زنجیره‌ای با پایه ۱۰۰ اعمال می‌شود. کاربر هیچ وزنی وارد نمی‌کند. اثر هر کالا از الگوی واقعی مخارج قبلی آن کالا به‌دست می‌آید: مجموع هزینه‌های ثبت‌شده قبلی بر تعداد ماه‌های تقویمی از اولین خرید تا ماه قبل تقسیم می‌شود تا «میانگین هزینه ماهانه تاریخی» ساخته شود. این روش باعث می‌شود کالاهای پرتکرار/پرهزینه اثر بیشتری داشته باشند و یک خرید حجیم منفرد با گذشت زمان اثر نامتناسب پیدا نکند. اگر سابقه هزینه معتبر وجود نداشته باشد، وزن برابر به‌عنوان fallback استفاده می‌شود.

`coverage` نشان می‌دهد چه سهمی از سبدِ دارای سابقه در آن نقطه دوباره قیمت‌گذاری شده است. تحلیل دسته‌بندی‌ها نیز تغییر کالاهای هر دسته را بر اساس سهم هزینه ثبت‌شده همان بازه ترکیب می‌کند. مقایسه فروشگاه‌ها همچنان میانگین قیمت واحد را بر اساس مقدار خرید وزن‌دهی می‌کند، نه صرفاً میانگین ساده رکوردها.

این شاخص برای پایش شخصی سبد خرید طراحی شده و جایگزین CPI رسمی نیست.

## پشتیبان، Import و Export

- **JSON:** پشتیبان کامل و خوانا
- **CSV:** مناسب Excel، همراه BOM و خنثی‌سازی ورودی‌های بالقوه Spreadsheet Formula Injection
- **فایل رمزدار:** `PBKDF2-SHA256` با ۶۰۰٬۰۰۰ iteration + `AES-256-GCM` از Web Crypto API
- محدودیت ورود مستقیم فایل پشتیبان: ۵۰ مگابایت
- اعتبارسنجی schema، نسخه، شناسه‌های تکراری، روابط Purchase→Product/Store و سازگاری مقادیر مالی
- دو روش Import:
  - **جایگزینی:** جایگزینی کامل داده پس از تأیید
  - **ادغام:** remap/یکپارچه‌سازی کالا و فروشگاه همسان، upsert رکوردها، حفظ تنظیمات نمایشی محلی و جلوگیری از ادغام واحد پول یا واحد مقایسه ناسازگار

JSON معمولی رمزگذاری نشده است. برای انتقال روی رسانه یا سرویس ثالث، از فایل رمزدار استفاده کنید.

## حریم خصوصی و آفلاین

قیمت‌نگار Analytics، Telemetry یا API برای ارسال داده خرید ندارد. داده خام در IndexedDB همان browser profile قرار دارد. فایل‌های خود اپ در اولین بارگذاری از میزبان استاتیک (مثلاً GitHub Pages) دریافت می‌شوند.

در build production یک Service Worker کوچک و اختصاصی تولید می‌شود که assetهای همان build را با cache versioned نگه می‌دارد. Workbox یا سرویس خارجی در runtime وجود ندارد. Service Worker در `npm run dev` عمداً ثبت نمی‌شود تا cache توسعه مزاحم hot reload نشود.

IndexedDB رمزگذاری سطح اپ نیست؛ شخصی که به همان دستگاه/پروفایل مرورگر دسترسی کافی داشته باشد ممکن است داده محلی را ببیند. «ذخیره‌سازی پایدار» فقط از مرورگر می‌خواهد داده کمتر در معرض پاک‌سازی خودکار باشد و جای Backup را نمی‌گیرد.

## پیش‌نیاز و اجرای محلی

Node.js سازگار با Vite 8 لازم است:

- Node `20.19+` در شاخه 20، یا
- Node `22.12+`

```bash
npm install
npm run dev
```

Vite معمولاً برنامه را روی `http://localhost:5173/` اجرا می‌کند.

برای بررسی منطق اصلی + TypeScript + build production + ساخت Service Worker:

```bash
npm run check
npm run preview
```

برای تست Offline/PWA از `npm run check` و سپس `npm run preview` استفاده کنید؛ حالت dev معیار تست Service Worker نیست.

برای بررسی dependencyهای runtime:

```bash
npm audit --omit=dev
```

از `npm audit fix --force` بدون بررسی breaking change استفاده نکنید.

## انتشار خودکار روی GitHub Pages

1. محتویات پوشه را در یک repository قرار دهید.
2. branch اصلی `main` یا `master` باشد.
3. در GitHub به **Settings → Pages → Build and deployment** بروید و Source را روی **GitHub Actions** بگذارید.
4. Push کنید.

Workflow در `.github/workflows/deploy.yml` قبل از Deploy این مراحل را انجام می‌دهد:

1. نصب dependencyها با Node 22
2. Audit وابستگی‌های runtime با سطح High
3. اجرای تست‌های منطق اصلی
4. TypeScript build و production build
5. تولید Service Worker نسخه‌دار
6. Deploy پوشه `dist` روی GitHub Pages

Vite با `base: './'` تنظیم شده، بنابراین هم User Pages و هم Project Pages پشتیبانی می‌شوند.

    backup.ts        # export/import، validation، CSV و encryption
    constants.ts     # نسخه و محدودیت‌های مشترک
    db.ts            # Dexie / IndexedDB
    demo.ts          # داده نمونه
    format.ts        # تاریخ، عدد و مبلغ فارسی
    merge.ts         # برنامه‌ریزی Merge و invariantهای واحد/ارز
    persian-date.ts  # نگاشت و پیمایش تقویم شمسی روی ISO داخلی
    pwa.ts           # ثبت Service Worker در production
    text.ts          # نرمال‌سازی جست‌وجو و deduplication
    types.ts         # مدل‌های داده
  App.tsx            # orchestration صفحات و state سطح اپ
  main.tsx           # bootstrap، Vazirmatn و PWA registration

scripts/
  test.mjs           # تست منطق pure بدون runner اضافی

جزئیات invariantها و تصمیم‌های معماری در `ARCHITECTURE.md` و تغییرات نسخه در `CHANGELOG.md` آمده است.
